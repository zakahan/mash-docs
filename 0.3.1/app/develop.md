# 扩展 Harness App

扩展调用行为时，需要同时考虑请求校验、单轮 Agent 配置和执行结束后的资源回收。本页以「为一次请求选择知识库」为例，说明各环节的职责与验证要点。

## 从请求字段到执行行为

| 环节 | 以知识库覆盖为例 |
|---|---|
| 请求校验 | 定义可选的知识库索引与后端类型，拒绝未知子字段。连接凭据和检索参数由部署提供。 |
| 请求处理 | 按同步或流式入口解析请求，校验成功后再准备本轮 Agent。 |
| Agent 装配 | 只应用本轮显式设置的字段，修改 Agent 副本，避免影响并发请求。装配失败时释放已经取得的资源。 |
| 后端管理 | 管理知识库实例及其复用，确保资源取得与释放匹配。 |
| 请求清理 | 正常完成、客户端中途断开和执行异常都应触发资源清理。 |

新增请求字段时，先定义可观察的行为。例如「请求 A 选择索引 A，同时请求 B 继续使用默认索引」。验证应覆盖字段校验、配置生效与并发隔离，不能只检查 JSON 能否解析。

## 跟踪绑定和刷新

创建绑定会话时先校验资源 ID，再解析控制面配置。扩展快照字段时，需要明确控制面字段与运行时配置的对应关系。消息处理过程读取 Session state、查找或重建实例快照，并合入本轮覆盖项；显式刷新还需更新会话固定版本。模型协议和技能资源最终由本轮 Agent 装配过程消费。

## 验证要点

使用测试模型或受控后端，覆盖以下行为：

- 参数校验、会话绑定和配置覆盖符合接口约定。
- 知识库实例正常复用，失败或取消后及时释放资源。
- 流式调用能够交付首个增量，并正确处理错误和客户端断开。
- 涉及会话元数据、模型参数或文件发布的改动，不破坏既有调用行为。

端到端验收使用与目标部署一致的身份模式，因为它决定哪些路由与请求级覆盖实际可用。接口字段和调用示例见 [Harness App 调用接口](../api/app.md)。
